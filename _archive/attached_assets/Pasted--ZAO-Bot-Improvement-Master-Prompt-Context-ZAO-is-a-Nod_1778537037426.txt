

ZAO Bot — Improvement Master Prompt

Context: ZAO is a Node.js Facebook Messenger bot running as a watchdog + child process pair with an Express web panel. The full codebase is attached. Your job is a complete audit and upgrade pass.

PHASE 1 — Deep Code Audit

Read every file in the project. For each file report:





Unhandled promise rejections and missing try/catch blocks



Memory leaks (uncleaned intervals, dangling event listeners, unbounded arrays/maps)



Race conditions (concurrent logins, simultaneous state writes)



Dead code, unreachable branches, unused imports



Hardcoded secrets or credentials that should be env vars



Any process.exit() calls that skip cleanup

PHASE 2 — Stability & Reliability Upgrades





Wrap every async command/event handler in a unified error boundary with structured logging



Replace all bare setTimeout restart logic with proper exponential backoff + jitter



Ensure MQTT reconnection never spawns duplicate listeners (use removeAllListeners before re-attach)



Add graceful shutdown hooks for SIGTERM, SIGINT, and uncaughtException that flush state before exit



Implement a circuit breaker on the login flow — if 3 consecutive logins fail within 10 minutes, pause and alert instead of looping forever



Add request queuing for outgoing messages to prevent burst failures



Ensure SQLite writes are serialized (no concurrent writes causing SQLITE_BUSY)

PHASE 3 — Web Panel Hardening





Enforce session expiry (max 2h idle timeout)



Add CSRF token validation on all POST endpoints



Rate-limit the login endpoint (max 5 attempts / 15 min per IP)



Sanitize all inputs before they touch the filesystem or database

PHASE 4 — Process & Memory Management





Add heap snapshot on Memory Guard trigger before recycling, saved to logs/heap-TIMESTAMP.heapsnapshot



Cap log files at 10MB with rotation (use winston or a simple size-check wrapper)



Ensure the Disk Guard prune runs before any backup write, not after



Validate that the Cookie Snapshot ring correctly overwrites the oldest entry and never exceeds 5 files

PHASE 5 — Configuration & Startup Validation





On boot, validate ZAO-SETTINGS.json against a schema — log a clear error and exit cleanly if required fields are missing or malformed



Check that all paths referenced in config actually exist; create missing directories automatically



Print a structured startup summary (Node version, config hash, active tier, panel URL) so the operator knows the state at a glance

PHASE 6 — Final Checklist

After all changes, confirm:





No unhandled rejections remain (node --trace-warnings clean)



All intervals and timeouts have corresponding clear references



No file is written without a try/catch around the write



The watchdog correctly detects and restarts a hung (non-crashing) child process



The web panel returns a proper 401 (not a 500) on bad credentials
